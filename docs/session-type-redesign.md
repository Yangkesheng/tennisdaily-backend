# 打球记录类型两级分类改造设计文档

## 1. 需求背景

新增和编辑打球记录时，将原有单级“打球类型”调整为两级分类，让用户先选择大类，再选择具体类型。

本次改造面向新增记录、编辑记录、记录详情、列表卡片、首页最近一次打球等场景。

## 2. 分类结构

| 一级类型 | 二级类型 |
|---|---|
| 日常球局 | 打单、双打 |
| 训练 | 发球、其他 |
| 比赛 | 单打、双打 |

## 3. 页面设计范围

| 页面/模块 | 设计调整 |
|---|---|
| 新增打球记录页 | 将“打球类型”改为一级 + 二级联动选择 |
| 编辑打球记录页 | 回显已保存的一级类型和二级类型 |
| 打球记录详情页 | 展示组合类型文案 |
| 打球记录列表页 | 卡片中展示组合类型文案 |
| 首页最近一次打球 | 如展示类型，使用新组合文案 |
| 日历点击某天记录列表 | 如展示类型，使用新组合文案 |

## 4. 新增/编辑页交互

### 4.1 组件结构

建议使用按钮组或分段选择器，不建议使用下拉框。

```text
打球类型
[ 日常球局 ] [ 训练 ] [ 比赛 ]

具体类型
[ 打单 ] [ 双打 ]
```

当选择不同一级类型时，二级类型区域动态变化。

### 4.2 一级类型选择规则

| 选择一级类型 | 展示二级类型 |
|---|---|
| 日常球局 | 打单、双打 |
| 训练 | 发球、其他 |
| 比赛 | 单打、双打 |

### 4.3 默认值建议

新增记录页建议默认：

| 字段 | 默认值 |
|---|---|
| 一级类型 | 日常球局 |
| 二级类型 | 打单 |

如果产品希望用户主动选择，也可以不默认二级类型，但保存前必须提示选择。

### 4.4 切换规则

- 切换一级类型后，二级类型需要随之切换为该一级类型下的合法选项。
- 建议切换一级类型时，将二级类型重置为该一级类型下的第一个选项。
- 二级区域只展示当前一级类型下的选项，不展示无关选项。
- 一级类型和二级类型都必选后才能保存。

### 4.5 编辑回显

编辑已有记录时，需要根据后端返回字段回显：

```text
示例：比赛 · 双打

一级类型：比赛
二级类型：双打
```

用户在编辑页切换一级类型后，二级类型按新一级类型重新选择。

## 5. 展示文案

列表、详情、首页最近一次打球建议统一展示组合文案。

| 一级类型 | 二级类型 | 展示文案 |
|---|---|---|
| 日常球局 | 打单 | 日常球局 · 打单 |
| 日常球局 | 双打 | 日常球局 · 双打 |
| 训练 | 发球 | 训练 · 发球 |
| 训练 | 其他 | 训练 · 其他 |
| 比赛 | 单打 | 比赛 · 单打 |
| 比赛 | 双打 | 比赛 · 双打 |

空间不足时可以只展示二级文案，但推荐优先展示完整组合文案。

## 6. 视觉建议

### 6.1 布局

- 一级类型作为主选择，视觉权重高于二级类型。
- 一级和二级之间保持清晰层级，可通过标题、间距、背景块区分。
- 移动端按钮点击区域建议不小于常规可点击热区。

### 6.2 状态

| 状态 | 建议表现 |
|---|---|
| 默认态 | 浅色背景或描边按钮 |
| 选中态 | 品牌主色背景或品牌主色描边 |
| 按下态 | 轻微透明度或背景变化 |
| 错误态 | 保存时未选择则在区域下方提示 |

### 6.3 错误提示

当未选择完整类型时，建议提示：

```text
请选择打球类型
```

或：

```text
请选择具体类型
```

## 7. 后端接口影响

本次后端已支持打球类型的一级类型和二级类型。新增和编辑请求推荐传 `category` / `subCategory`，响应会返回完整展示字段；旧 `type` 字段仍保留兼容。

### 7.1 建议字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `category` | number | 一级类型枚举值，新增/编辑请求和响应使用 |
| `categoryText` | string | 一级类型展示文案，响应返回 |
| `subCategory` | number | 二级类型枚举值，新增/编辑请求和响应使用 |
| `subCategoryText` | string | 二级类型展示文案，响应返回 |
| `typeText` | string | 组合展示文案，响应返回 |

### 7.2 枚举建议

一级类型：

| 枚举值 | 展示文案 |
|---:|---|
| `1` | 日常球局 |
| `2` | 训练 |
| `3` | 比赛 |

二级类型：

| 一级类型 | 二级枚举值 | 展示文案 |
|---:|---:|---|
| `1` | `1` | 打单 |
| `1` | `2` | 双打 |
| `2` | `3` | 发球 |
| `2` | `4` | 其他 |
| `3` | `1` | 单打 |
| `3` | `2` | 双打 |

### 7.3 需要调整的接口

| 接口 | 是否需要调整 | 说明 |
|---|---|---|
| `POST /api/sessions` | 是 | 新增记录时提交一级类型和二级类型 |
| `PUT /api/sessions/:id` | 是 | 编辑记录时修改一级类型和二级类型 |
| `GET /api/sessions/:id` | 是 | 详情和编辑页需要回显新字段 |
| `GET /api/sessions` | 是 | 列表和按日期查看需要展示新字段 |
| `GET /api/sessions/latest` | 建议调整 | 首页最近一次打球可能展示类型 |
| `GET /api/home/summary` | 建议调整 | `latestSession` 内如展示类型，需要同步新字段 |
| `GET /api/sessions/calendar` | 视情况调整 | 如果图表或列表展示类型占比，需要同步口径 |
| `GET /api/stats/month` | 视情况调整 | 如果统计按类型展示，需要同步口径 |

## 8. 请求与响应示例

### 8.1 新增打球记录

```json
{
  "date": "2026-06-27",
  "durationMinutes": 120,
  "rating": 4,
  "category": 1,
  "subCategory": 1
}
```

### 8.2 打球记录详情返回

```json
{
  "id": 12,
  "date": "2026-06-27",
  "durationMinutes": 120,
  "rating": 4,
  "category": 1,
  "categoryText": "日常球局",
  "subCategory": 1,
  "subCategoryText": "打单",
  "typeText": "日常球局 · 打单"
}
```

## 9. 兼容旧数据

当前后端已有旧字段 `type`，旧枚举如下：

| 旧类型 | 含义 |
|---:|---|
| `1` | 双打 |
| `2` | 单打 |
| `3` | 训练 |
| `4` | 单打比赛 |
| `5` | 双打比赛 |

建议迁移或兼容映射：

| 旧类型 | 新一级类型 | 新二级类型 |
|---|---|---|
| 双打 | 日常球局 | 双打 |
| 单打 | 日常球局 | 打单 |
| 训练 | 训练 | 其他 |
| 单打比赛 | 比赛 | 单打 |
| 双打比赛 | 比赛 | 双打 |

说明：

- “训练 · 发球”是新增细分类型，旧训练数据无法自动识别，默认归为“训练 · 其他”。
- 后端可短期保留旧 `type` 字段，前端优先使用新字段展示。
- 如果历史数据不迁移，后端返回时需要根据旧 `type` 衍生新展示字段。

## 10. 校验规则

前端和后端都需要校验组合是否合法。

| 一级类型 | 合法二级类型 |
|---|---|
| 日常球局 | 打单、双打 |
| 训练 | 发球、其他 |
| 比赛 | 单打、双打 |

非法组合示例：

| 一级类型 | 二级类型 | 结果 |
|---|---|---|
| 日常球局 | 发球 | 不允许 |
| 训练 | 双打 | 不允许 |
| 比赛 | 其他 | 不允许 |

## 11. 比赛成绩联动

当前后端已有 `matchRank` 比赛成绩字段。

建议联动规则：

- 一级类型为“比赛”时，可以展示比赛成绩字段。
- 一级类型为“日常球局”或“训练”时，隐藏比赛成绩字段。
- 非比赛类型保存时，后端会将 `matchRank` 归零。

## 12. 设计验收点

- 新增记录页可以选择一级类型和二级类型。
- 二级类型随一级类型变化。
- 切换一级类型后，不会保留非法二级类型。
- 编辑页能正确回显历史记录类型。
- 列表、详情、首页最近一次打球展示文案一致。
- 未选择完整类型时，保存有明确提示。
- 比赛成绩字段只在比赛类型下展示。
